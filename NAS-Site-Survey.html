StillWorks LegalOS · Integration Field Guide

NAS Site Survey

A step-by-step checklist for collecting every Synology SMB/CIFS detail the app needs. Work top to bottom while you're on site — each step unlocks the next, and the last step verifies the whole thing works before you leave.

Access method: SMB / CIFS Synology DSM Est. on-site time: 45–60 min

Before you go

  • A laptop you can join to the office Wi-Fi / LAN (or a workstation the firm will let you use).
  • This checklist — printed or open on your phone.
  • A camera / phone for screenshots of DSM screens and the folder tree.
  • Login to the NAS admin console (find.synology.com or the NAS IP in a browser).
  • The office manager or IT contact who can create users and confirm policy.
01

Identify the NAS hardware

Model, DSM version, physical location.

  • model
  • DSM version
  • serial no.
  • where it sits

How to get it

  1. Log in to the DSM web console and open Control Panel → Info Center.
  2. Note Model Name, DSM version, and Serial Number.
  3. Ask where the box physically lives (server room, cabinet) and who has the key.

Why it matters: the model determines which SMB protocol versions and features (encryption, snapshots) are available — this decides what the integration can promise.

02

Record the network identity

Hostname, static IP, subnet, gateway — and whether users are on the same LAN.

  • hostname
  • IP (static?)
  • subnet / gateway
  • same LAN? / VPN?

How to get it

  1. Control Panel → Network → Network Interface → select LAN. Note whether IP is static or DHCP.
  2. Hostname: Control Panel → Network → General.
  3. On a workstation, confirm the subnet and name resolution:
> ipconfig /all          # subnet, gateway, DNS
> ping DS920             # resolves hostname → IP
> nslookup DS920         # if ping fails by name
  1. Ask whether staff ever work offsite. If yes, note whether a VPN is in place — it changes whether SMB alone is enough.

Why it matters: the app reaches the NAS by a stable hostname or IP. A drifting DHCP address breaks every document read/write, so it must be static or reserved.

03

Confirm SMB service settings

SMB on, protocol range, workgroup, port.

  • SMB enabled
  • min / max SMB
  • workgroup
  • port (445)

How to get it

  1. Control Panel → File Services → SMB tab.
  2. Confirm Enable SMB service is ticked.
  3. Note the minimum/maximum SMB protocol (want SMB2+; ideally SMB3).
  4. Note the Workgroup (default WORKGROUP) and whether SMB3 encryption is offered.
  5. Sanity-check reachability from Windows:
> net view \\DS920        # lists shares if SMB is reachable

Why it matters: this tells us which SMB library and protocol level to use, and whether transport encryption is available for sensitive legal files.

04

List the shares and pick the working share

Share name(s), the base path, capacity and quota.

  • share name
  • base path inside
  • capacity / used
  • quota

How to get it

  1. Control Panel → Shared Folder → note every share name.
  2. Pick the share the firm wants for case files (e.g. LegalOS).
  3. Open it in File Explorer via \\DS920 and note the base path where case folders should sit.
  4. Capacity/quota: Shared Folder → select → Edit → Info, or Control Panel → Storage Manager.

Why it matters: the share name + base path map directly to the app's nasPath / nasFolder fields and become the mount point for every upload and download.

05

Document the folder structure

Naming convention, a real sample path, existing files to migrate.

  • organised by
  • sample path
  • case-number scheme
  • existing files?

How to get it

  1. Browse the share in File Explorer and screenshot the tree.
  2. Ask the office manager how folders are organised — by case number, client, or practice area.
  3. Ask for one real example, e.g. \LegalOS\Cases\2024-CR-001\.
  4. Ask whether there is already a NAS full of files to import, or whether we start clean.

Why it matters: this drives the path-mapping logic (case number → folder) and decides whether the rollout includes a one-time migration of existing files into the database with hashes.

06

Create the service account

A dedicated NAS user, least-privilege to the LegalOS share only.

  • username
  • password
  • domain (if AD/LDAP)
  • read/write scope

How to get it

  1. Control Panel → User & Group → Create → make a service account (e.g. legalos_svc).
  2. Set permissions on the share only: Shared Folder → select → Edit → Permissions → grant Read/Write to this account, nothing else.
  3. If the NAS is joined to AD/LDAP, note the domain and whether to use a domain account instead.
  4. Record the password securely — it goes into the app's config (encrypted).

Why it matters: one service account keeps NAS credentials out of each employee's hands. Least-privilege limits the blast radius if that account is ever compromised — the app's own role-based access control sits on top.

07

Record file rules and retention

Allowed types, max size, version count, deletion policy.

  • allowed types
  • max file size
  • versions kept
  • deletion policy

How to get it

  1. Ask which file types the firm works with (PDF, DOC/DOCX, XLSX, scans, images, archives).
  2. Ask the largest single file they'd ever store.
  3. Ask how many prior versions they want to keep.
  4. Check recycle bin: Shared Folder → Edit → Recycle Bin — note if deletions should go to a bin first.

Why it matters: these become the upload-validation limits and the version/retention behaviour of the documents feature.

08

Capture security & compliance

Encryption, backups, admin access, regulatory constraints.

  • volume encryption
  • backup (Hyper Backup / snapshot)
  • NAS admins
  • DPDP / retention rules

How to get it

  1. Encryption: Shared Folder → Edit → Encryption — note on/off.
  2. Backups: Control Panel → Hyper Backup / Snapshot Replication — note what's scheduled and who owns it.
  3. Ask who holds NAS admin rights outside the app.
  4. Ask about any bar-association or data-protection obligations (e.g. India DPDP Act) affecting retention and deletion.

Why it matters: legal files are sensitive personal data. Encryption at rest, a real backup, and clear ownership are non-negotiable before the app goes live.

09

Verify connectivity before you leave

Prove the app can reach and write to the share — not just note it down.

  • ping OK
  • share reachable
  • read/write test
  • firewall allows 445

How to get it

  1. Map the share with the service account:
> net use Z: \\DS920\LegalOS /user:legalos_svc *
  1. Write and read a test file on Z:, then delete it.
  2. Check the firewall allows SMB from the office subnet: Control Panel → Security → Firewall.
  3. Confirm the port: Control Panel → File Services → SMB shows port 445.

Why it matters: the most common integration failures are firewall rules and permissions — catching them on site avoids a second visit.
